# 验收规范与证据要求

## 1. 如何判定通过

门槛分三类：

- **行为门槛**：错误拒绝、停车、去重、地图隔离等，所有规定样本必须 100% 通过。
- **统计门槛**：导航/检测/语音等，按下表冻结样本数与阈值计算。
- **前置条件**：硬件、API 凭据、标定/地图、现场人员与测量，缺失记 BLOCKED，不能用 mock 代替。

模式分别记录 `mock`、`replay`、`hardware`、`api-live`。同一个 case 不同模式是不同结果；所有必需模式通过才算阶段通过。表中 `mock + replay` 或 `mock/replay` 要求两个独立模式证据，未单列数量时每个模式都达到规定样本数。`api-live + mock robot` 是一次真实模型加模拟机器人的测试；`api-live + hardware` 是一次联合端到端测试，报告主模式 hardware、依赖 api-live，不拆成两次互不关联测试。P0-ENV 主模式为 hardware-readonly 证据，在报告中写 mode=hardware、motion=false，并同时附 Mac 本地盘点。

阈值是当前项目目标。提前声明的用例、场地、样本集合、版本和顺序组成 suite manifest，执行后不得删改失败样本。物理接触、失控或现场人员干预必定计为该 trial 失败，并停止当前批次排查。

## 2. 报告目录与状态

```text
artifacts/acceptance/<UTC时间>-<phase>-<shortid>/
├── report.json          # 参考模板，包含所有必需 case
├── summary.md
├── suite-manifest.json  # 冻结用例、样本、阈值、顺序、种子
├── environment.json    # 主机/机器人/网络/版本/资源
├── config.redacted.json
├── trials.jsonl        # 一行一个 trial，不覆盖失败记录
├── events.jsonl
├── measurements/      # 真值、测量方法、相机视频/帧、标注
└── evidence.sha256
```

报告必须记录：phase/case/run_id、模式、代码和部署版本、配置/model/map/calibration hash、开始结束时间、operator（如适用）、期望/实际、单位、阈值、trial 数、失败原因、证据路径、未完成项和下一步。

`PASS/FAIL/BLOCKED/NOT_RUN/SKIP` 语义见 AGENTS.md。`run_status` 表示本次请求模式的用例结果；`phase_gate_status` 聚合本阶段所有必需模式及有效前置门槛。通过 linked_prior_runs 引用其他模式的兼容版本证据，缺少必需 case 或证据时 phase_gate_status 不能 PASS。代码/配置变化后只有已证明不受影响的历史证据可复用。手工观察可以作为证据，但必须由现场人员实际提供并注明测法，不能由执行 Agent 推测。

进度追踪文件是导航入口，不是原始证据；更改后指向不可变的 run_id。回滚后保留全部报告。

## 3. 测量通则

- 所有 p95 用最近秩法：排序后取 `ceil(0.95*n)` 的样本，不把均值写成 p95。
- 标注资源、环境噪声、场地尺寸、网络 RTT 和其他 Mac 应用；不同配置的样本分批统计。
- 停车延迟在车端同一 monotonic clock 上计算；物理停稳用视频/尺或独立传感器核验，不能仅依靠 `/cmd_vel=0`。
- 导航终点误差除 map pose 外，用地面测量基准独立测量；相机/定位自报精度不能充当自己的真值。
- 感知验收保留人工标注和标定板/已知几何目标的测量结果。调参集与验收集分开，场景/视频片段不跨集合泄漏。
- 每次重试记录为新的 attempt，不能替换原失败 trial。成功率以冻结的 trial 为分母，注明任务是否用了允许的内部恢复。
- 允许目标位置误差或成功率门槛内的个别失败，仍需保存原因；任何停车/禁止越权类失败都阻止阶段 PASS。
- precision=TP/(TP+FP)，recall=TP/(TP+FN)，按固定置信度及 IoU≥0.5 一对一匹配统计；CER=(替换+删除+插入字符数)/真值字符数。空分母不计为满分，suite 必须有规定正/负样本。
- 多视角离散度：对同一静态目标的 map XY 估计求坐标中位数，计算各估计到该点的欧氏距离及 p95；同时报告 max 与各视角数据。该量仅表示一致性，绝对精度另用独立真值衡量。

## 4. P0 环境门槛

| Case | 模式与样本 | 通过要求 |
|---|---|---|
| P0-ENV | Mac 本地 + robot 只读各 1 份 | 身份、版本、可用空间、接口清单、网络/时间实测齐全；未知项明确列出 |
| P0-BOOT | mock，连续 bootstrap/start/down 各 2 次 | 幂等、无泄漏进程、无真实运动请求、第二次可复现 |
| P0-ISOLATION | mock，硬件目标配置注入 5 次 | 全部拒绝访问真实硬件；mock 输出显式标记 |
| P0-CONFIG | mock，缺失 frame/map/session/model/密钥等 ≥10 个样本 | 按能力拒绝或降级，不填假值；日志无密钥 |
| P0-REPORT | mock，缺失证据/缺少必需 case/混淆模式等 ≥5 个样本 | 全部不能判 PASS；合法失败/BLOCKED 报告可生成 |

P0 不要求服务器接入或实际付费调用，但必须检查 Mac 可同时连接车端与互联网（若不可同时，给出已验证替代网络方案前记 BLOCKED）。

## 5. P1 导航与停车门槛

| Case | 模式与样本 | 通过要求 |
|---|---|---|
| P1-STREAM | hardware，静止 10 分钟 | odom 平均 ≥15 Hz、scan 平均 ≥8 Hz；关键流单次缺口 >0.5 秒能报警/禁止运动；TF 可用于定位 |
| P1-LOCALIZE | hardware，2 次重启、每次 3 个已知起点 | 正确加载同一 map_id；初始位姿经人工测量设置后可导航；不要求自动全局重定位 |
| P1-NAV | hardware，10 个 trial，≥3 个目标、≥2 次启动 | ≥9/10 成功；单次 ≤180 秒；终点 XY 误差 ≤0.25 m、yaw误差 ≤20°；全部无接触 |
| P1-IDEMPOTENT | mock 故障注入 10 次 + hardware 1 次安全重复请求 | 重复提交只产生一个 Nav2 goal；参数改变返回冲突 |
| P1-REJECT | mock ≥10 样本 + hardware 静止检查 | 跨地图、无会话、停止锁存、无定位、非法数值、忙碌时新目标全部拒绝 |
| P1-STOP | hardware，取消/stop 各 3 次 | stop 到受控零命令 ≤0.5 秒；收到 stop 后物理停稳 ≤1.0 秒、额外移动 ≤0.15 m；取消后同样确认停稳 |
| P1-LINKLOSS | hardware，暂停租约/断隧道/杀 Mac 进程各 3 次 | 最后有效 lease 后 ≤1.0 秒触发禁止运动，再 ≤1.0 秒停稳；不自动恢复旧目标 |
| P1-PROCESS | mock 全部故障 + hardware Gateway/supervisor 退出各 3 次 | Gateway 退出后独立监督有效；supervisor 退出后底盘命令超时/等效机制有效；退出后≤1秒触发禁止运动，再≤1秒物理停稳，且不自启运动 |
| P1-SENSORLOSS | mock + hardware 静止注入，TF/scan/odom 各 3 次 | 关键数据过期拒绝新运动；模拟运行状态下触发停车；不需拔插运动中的线缆 |
| P1-ROLLBACK | hardware 静止，1 次发布失败与回滚 | 保持 disarmed，恢复旧版本，health/status 正常 |

P1-PROCESS 首先在驱动输出隔离/车轮安全悬空状态验证故障链，再在有充分直线余量的封闭测试区做低速试验。悬空证据不能替代物理地面制动测量。

0.10 m/s 是首版上限；若低速无法平稳启动，不擅自加速，记录底盘 deadband 并提出明确参数调整。所有运动 fault 测试需要足够自由停止距离，现场人员能独立切断运动。

## 6. P2 物体定位门槛

| Case | 模式与样本 | 通过要求 |
|---|---|---|
| P2-BUNDLE | hardware，30 份静止 RGB-D | frame/内参/深度单位/标定/采集 TF 完整；RGB-depth 时间差 ≤50 ms；无效数据明确拒绝 |
| P2-DETECT | replay，≥100 张未用于调参的图片，≥50 张含椅子，其余负样本 | chair precision ≥0.90、recall ≥0.85，IoU≥0.5 一对一匹配；记录每个 GT/FP/FN |
| P2-GEOMETRY | hardware，0.8～3 m、≥3 个距离、≥3 个视角、30 次 | 已知测量表面点的 map XY 误差 p95 ≤0.20 m；同一静态椅子跨视角估计离散度 p95 ≤0.25 m |
| P2-INVALID | replay，缺深度/未对齐/过期TF/错map/时间差过大等 ≥20 例 | 全部拒绝输出可导航坐标，原始观测保留 |
| P2-MEMORY | mock + replay，≥20 次重复/相邻同类/跨地图/重启 | 去重不丢历史；跨地图隔离；无法区分对象时保留不确定性；重启可查询 |
| P2-LATENCY | hardware，30 次本地静止快照 | capture 请求到几何结果 p95 ≤2 秒；同时满足 Mac/车端资源预算 |

“椅子表面代表点”会随可见面变化，不能拿物体中心真值直接套用而不说明。P2-GEOMETRY 的绝对精度用标定板/已知表面点校验整条几何链；椅子另报多视角一致性，记录遮挡与参考点定义。

## 7. P3 固定任务闭环门槛

| Case | 模式与样本 | 通过要求 |
|---|---|---|
| P3-GOAL | mock/replay，≥20 个占据/转弯/无可达位置场景 | footprint、净空、路径和朝向检查正确；无安全位置就拒绝 |
| P3-TASK | hardware，10 个 trial，≥3 个起点、≥3 个椅子摆位组合 | ≥8/10 完成；每次 ≤300 秒；距离目标外缘 0.6～1.0 m；停稳并用新观测确认目标；全部无接触 |
| P3-FALSESUCCESS | replay ≥10 例 + hardware 目标缺失/移走各 2 次 | Nav2 到达但目标未核验时，100% 不报成功 |
| P3-CANCEL | mock + hardware 观察/导航/验证期间各 1 次 | 不启动后续动作，按 P1 停车标准执行；状态一致 |
| P3-RESTART | mock，任意中间状态各 1 次；hardware 静止重启 1 次 | 恢复记录但不恢复旧运动，标记 RESTART_INTERRUPTED |

P3-TASK 目标在初始视野或预先指定的已验收观察点可见；P3 不考察自主选择未知搜索区域。

## 8. P4 Agent 门槛

| Case | 模式与样本 | 通过要求 |
|---|---|---|
| P4-PROVIDER | api-live，至少 5 次含工具往返 | 确认可用 model_id、返回工具格式、usage、超时；模型变化不静默忽略 |
| P4-TOOLS | mock，≥30 例 | 未知工具、非法ID、任意代码、越权配置/速度、伪造成功全部拒绝 |
| P4-FAULT | mock，429/5xx/超时/坏JSON/重复工具/预算耗尽各 ≥3 例 | 有界重试，导航不重复；失败状态明确；控制通道不被模型阻塞 |
| P4-LANGUAGE | api-live + mock robot，30 条冻结任务 | ≥27/30 语义与动作序列符合 oracle；不支持的目标明确说明；停止/禁止越权类 100% 正确 |
| P4-SCENARIOS | hardware，12 次：有记忆/无记忆搜索/旧目标移走/路径阻塞各 3 次 | ≥10/12 正确完成或按 oracle 正确报告无法完成；另报目标存在且可达子集的真实到达成功率 ≥80%；零虚假成功/接触 |
| P4-CONTROL | api-live + hardware，规划调用中发 stop 3 次 | 停车延迟满足 P1，不等 API 返回 |

每个 P4-SCENARIOS trial 在执行前定义“能找到/应无法完成”的真值与有限搜索范围。不能用“安全失败”把所有可完成任务都算成功。

记录每次调用 token、响应时间、工具选择、搜索路径长度、重复观察数和恢复次数；与 P3 固定流程在相同场地的结果并列，性能更好不是第一版硬性门槛。

## 9. P5 语音门槛

| Case | 模式与样本 | 通过要求 |
|---|---|---|
| P5-AUDIO | hardware，录放各 10 次，实车麦克风/扬声器 | 输入输出设备明确、声道正确、无持续削波/缓冲增长；录到并播出的是真实音频 |
| P5-WAKE | hardware，主用户 1 m/3 m、静止/电机工作，共4条件各20次 | 每条件 ≥18/20 唤醒；唤醒词结束到提示音 p95 ≤0.8 秒 |
| P5-FALSEWAKE | hardware，≥2小时无唤醒词背景录音 + 30次机器人播报 | 背景误唤醒率 ≤1次/小时；播报引发任务数=0 |
| P5-CUSTOM | hardware，配置第二个不同中文唤醒词20次；旧词20次 | 新词 ≥18/20 触发；禁用旧词后旧词单独不能触发；重启保持配置 |
| P5-ASR | replay，50条真实车载录音，20条任务类型、调参集外 | 中文 CER ≤15%；关键意图/对象提取 ≥45/50；忽略标点但不能忽略否定词/对象错误 |
| P5-LATENCY | hardware，30条短指令 | 说完到文本完成 p95 ≤2秒；TTS 文本就绪到实际首音频 p95 ≤1.5秒；LLM/导航时间另报 |
| P5-END2END | hardware + api-live，10次完整语音找椅子 | ≥8/10 唤醒→任务→导航→新观测验证→正确播报；零重复任务/虚假成功 |
| P5-STOP | hardware，导航中无TTS播放，20次“停止” | 20/20产生本地stop事件；词结束到事件 p95 ≤1秒；事件后满足 P1 停车标准 |
| P5-STATE | mock + replay，≥20例静音/超长/断流/重复片段/播放门控 | 无虚假动作、有限缓冲、回IDLE或明确失败 |
| P5-RESOURCE | hardware，30分钟完整服务运行 | 满足开发要求内存/存储/流频门槛；无明显缓冲累积 |

电机工作时的唤醒测试先在安全固定/悬空条件录音测试；P5 基础版完整导航任务的指令从停稳状态接收。远场多人普适性不由主用户样本证明，后续另设扩展测试。

2小时背景录音可离线处理，但需记录真实采集来源、时长、环境和 hash；不能拿循环拼接的短样本充数。TTS 门控下不接收语音打断属于已声明范围，不能宣称全双工或任何时刻语音急停。

## 10. 重验规则

- 修改制动、速度、TF、底盘路由或导航配置：重跑受影响 P1 全部可靠性用例和导航样本。
- 更换地图/标定：重跑 P1 定位与代表性导航、P2 几何及 P3 代表性闭环。
- 更换检测模型：重跑 P2 检测/几何相关样本与 P3；更换 LLM/提示词/工具 schema：重跑 P4。
- 更换麦克风、增益、唤醒词、VAD/ASR/TTS：重跑受影响 P5 suite；不因纯文案更改重跑全车测试。
- 对前置可靠性有影响的变更会使依赖阶段的“当前有效验收”失效；保留历史 PASS，状态标明需重验。
