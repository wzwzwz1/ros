# 架构与技术决策

## 1. 数据与控制路径

```text
机器人                                        Mac M4 / 16 GB
RGB-D / LiDAR / TF ── Robot Gateway ──SSH──→ 感知与坐标定位
音频采集/播放       ←──────────────────────→ KWS / VAD / ASR / TTS
                                              ↓
                                        SQLite 空间记忆
                                              ↓
                                        任务状态机 / Agent ──→ DeepSeek API
                                              ↓                   │ 工具提议
Nav2 ← Robot Skills ← Gateway ←──────── 参数与前置条件校验 ←───────┘
  ↓
车端独立运动监督/速度仲裁 → STM32 → 底盘
```

Mac 上的 Agent 拥有任务生命周期，车端拥有运动执行权和最终禁止运动能力。LLM 工具调用提议必须经本地确定性校验，无法自行绕过监督器。

## 2. 通信方案

- 首版采用车端 HTTP/WebSocket Gateway；Mac 无须安装 ROS，也不依赖跨机器 DDS 自动发现。
- Gateway 默认只监听车端 `127.0.0.1:8765`，Mac 用 SSH 隧道映射到本机 `127.0.0.1:8765`；Mac 应用/调试页为 `127.0.0.1:8080`。端口可配置，冲突即报错，不杀占用进程。
- HTTP 用于命令和状态；WebSocket 用于事件和音频。RGB-D 首版采用按需快照，限制图像尺寸、频率和缓冲区。
- Gateway API 使用本项目随机访问令牌，限制来源与请求大小；不会向公网开放机器人控制端口。
- 浏览器只连接 Mac 应用，由 Mac 后端连接 Gateway。任何调试页“停车”都直接走本地控制逻辑，不经过 LLM。
- 需要上网调用 API 时，必须同时验证“Mac → 机器人”和“Mac → DeepSeek HTTPS”可达。机器人热点本身不能被假定有互联网。优先保持机器人网络，用 Mac 的另一网络接口上网；否则先规划共同局域网接入与回退。P0 不自动切换/关闭热点。

## 3. 运动执行设计

- 所有导航经 Nav2 Action；首版允许一个活跃导航。新的目标不会隐式抢占旧目标，需明确取消并确认停止或完成后再提交。
- Nav2 输出接入本项目独立监督/仲裁层，再转发到底盘输入；具体 topic 名称在 P1 探测后配置，不能假定厂商 driver 已支持超时停止。
- 监督层对有效运动会话、Mac 控制租约、本地关键节点、传感器新鲜度和速度约束作判断。Mac lease 每 250 ms 续约，车端 1 秒未收到续约即撤销运动许可。
- 监督层失效后的最后一层停车依赖需实测：底盘控制器命令超时，或具有等效效果的独立机制。若无法证明，P1 硬件门槛失败，不能启用无人值守执行。
- 运动租约与 LLM 请求线程独立；任务在 NAVIGATING 状态可正常续约，LLM 长调用不阻塞停车。Mac 任务监督器死亡、状态不再有效或整个进程挂起时，租约停止。
- 键盘、手柄与本项目不能同时绕过仲裁控制底盘。P1 列出所有速度发布者并验证只有受控路径。
- `cancel` 是取消具体导航；`stop` 撤销运动权限、取消导航并要求零速度。stop 锁存，只有现场已确认且故障解除后显式重新 arm 才能运动。
- 首版限制线速度 0.10 m/s，禁止倒车和原地旋转恢复；如果阿克曼在某路径上必须倒车，则报告不可达，后续单独验证倒车策略。

默认阈值与停车验收见 [验收规范](acceptance.md)。阈值不能代替真实制动距离和路径净空验证。

## 4. 定位与地图

- 建图沿用 Cartographer；任务运行使用冻结的二维栅格地图及已验收的定位模式，默认评估厂商 Nav2 + AMCL。
- 首版一次只允许一个 `map → odom` 发布来源。建图与定位模式相互排斥，不把 Cartographer 和 AMCL 同时作为同一 TF 的权威。
- `map_id` = 地图图像、YAML 几何元数据及坐标系版本的内容哈希。地图更新、重建或坐标原点变化，均生成新 ID。
- 每张地图带 manifest：图像/YAML 路径与哈希、分辨率、原点、frame、已标定区域、允许行驶范围、固定观察点、人工测量基准及初始位姿设置方式。
- memory 与目标均绑定 map_id。切换地图禁止沿用旧物体坐标；需要人工定义并验证坐标变换后才能做显式迁移。

## 5. RGB-D 定位

机器人同步采集 RGB、深度、CameraInfo 和同一采集时刻的 TF，Gateway 返回不可变的 observation bundle。Mac 根据检测框/掩膜、深度与标定产生几何观测。

坐标路径：`RGB 像素 → 已对齐深度 → camera optical XYZ → base → odom → map`。

首版停车拍照降低运动模糊和时序误差；需要记录“采集时刻的 TF”，不能在图片到达 Mac 后使用最新 TF。图像和深度未对齐时，不允许直接按同像素取深度。

物体位置首先定义为检测到的可靠可见表面代表点，不自动等同于椅子中心或朝向。物体占据范围由检测/深度估计，并与局部 costmap 共同决定可达停车位置。

## 6. 首版模型选择

| 能力 | 默认 | 加载策略 | 替代条件 |
|---|---|---|---|
| 检测 | YOLO11n | Mac 本地；先 ONNX/原生验证，再比较 CoreML | 召回不足时评测 YOLO11s 或 n-seg，保留原基线 |
| 唤醒 | sherpa-onnx 中文 KWS | P5 默认 Mac；后续可测车端占用 | 厂商模块支持自定义且可读音频时可复用，但须通过同一验收 |
| VAD | Silero VAD | 本地常驻 | 以真实车载录音验证结束判断 |
| ASR | SenseVoiceSmall 量化 ONNX | 本地按句识别 | 不把流式字幕作为首版验收要求 |
| TTS | sherpa-onnx `vits-melo-tts-zh_en` | Mac 合成，小车播放 | 厂商 TTS 仅可作经过验收的适配器 |
| LLM | DeepSeek Flash 系列官方 API | P4 默认文本工具调用 | P4 capability probe 确认有效 model_id；效果不足再评测 Pro |
| VLM | 首版不必需 | 需要语义核验时按需调用 | Qwen3.5-4B 4-bit/MLX-VLM，或另行启用视觉 API |

固定类别检测器只能识别其训练类别。P4 工具返回支持的类别；不能把用户提到“灭火器/垃圾桶”直接当成默认 YOLO 已支持。新增类别需要模型、数据与验收一起扩展。

DeepSeek 文本模型不可假定支持图片。视觉实验 API 与默认文本模型分开配置、探测和验收。默认上传文本与结构化观测，不上传持续视频/音频。

模型与运行时的来源见 [参考资料](references.md)，实际版本进入 `models.lock.json`。开源代码与具体权重许可分别记录。

## 7. 记忆与规划

- SQLite 保存不可变 observation 和可更新 object 两层；任务日志独立表。简单几何查询优先，不要求向量数据库或嵌入模型。
- 支持对象生命周期：tentative、confirmed、stale、not_found、superseded；未看到一次不等同于对象已消失。
- 更新依据包含标签、距离、观测覆盖、时间和不确定性；无法确定同一实体时保留两个候选，不静默合并。
- P3 固定状态机作为基线；P4 只替换高层选择与解释，复用 P3 的目标生成、导航、校验和失败状态。
- LLM 只能选择已存在的对象/观察点 ID，不能随意发明坐标。较底层的导航 API 可接受坐标，但不直接暴露给语言模型。
- 规划与记忆检索、移动、再观察的每步都有预算。已知地图上的预设观察点搜索先于无地图主动探索。

## 8. 语音行为

默认半双工：IDLE → WAKE_ACK → LISTENING → TRANSCRIBING → DISPATCHING → EXECUTING → SPEAKING → IDLE。

- 唤醒提示后只收一条指令，VAD 判断结束。播报期间屏蔽普通唤醒/指令输入，避免自唤醒。
- 语音和文字进入同一任务接口，不能旁路调用原始速度。
- P5 基础版测试“停车接收任务、执行、停稳后播报”；不承诺边走边远场连续对话。
- 执行中支持高优先级“停止”，在未播放 TTS 时绕过普通唤醒走本地关键词事件。使用专门 stop detector；仍以车端租约及现场物理停车方式处理失联或漏识别。
- 播报期间的语音打断/语音停止需要 AEC 或可靠输入门控，作为 P5B 扩展；基础版仍有界面停车和现场停车。

## 9. 暂不实施的扩展

无地图 frontier 探索、复杂三维 scene graph、人员身份识别、声纹、声音克隆、自动楼层切换、远程无人值守、任意 shell 工具、长期自主巡航不属于 P0～P5 基础范围。
